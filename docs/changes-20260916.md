## 1. 폰에서 쓸 길 — 없었다 → 생겼다

| | AS-IS | TO-BE |
|---|---|---|
| 폰 앱 | 없음 (설치형 PWA 만) | 안드로이드 앱 — 화면 6개 + 담기 판 (`native/`) |
| 폰 ↔ DB | **못 붙음.** `db/policy.sql` 이 RLS 를 켜고 정책을 0개로 둬서 REST 도 닫혀 있다 | `web/app/api/` 경로 15개 |
| API 인증 | — | `APP_API_TOKEN` 없으면 **전체 503** (`lib/api/guard.ts`, fail closed) |
| 로직 위치 | 서버 액션 안 | `lib/` 로 뺐다 — **웹 화면과 API 가 같은 SQL 을 부른다** |
| 순수 층 | 웹만 씀 | Metro 가 `web/lib/` 을 **복사 없이 그대로 읽는다** (`native/metro.config.js`) |
| 유출 방지 | tsc 뿐 (`web/node_modules` 에서 `pg` 타입을 찾아내고 통과시킨다) | CI 가 **안드로이드 번들을 grep** 한다 |

왜 API 가 먼저였나: 로그인이 없어도 안전했던 이유는 **서버만 DB 에 붙기 때문**인데,
HTTP 문을 열면 그 전제가 깨진다. 그래서 문과 자물쇠를 같이 냈다.

## 2. 흐름을 따라가며 — 머리말이 내용을 밀어냈다

항목을 하나씩 고쳤는데도 "그대로 같다" 는 말이 나왔다. 맞는 말이었다 —
고친 것들이 화면에 안 씌어 있었다. 폰 크기(390×844)로 **재서** 고쳤다
([`ui-references.md`](ui-references.md) 9장).

| | AS-IS | TO-BE |
|---|---|---|
| 장보기 첫 재료가 나오는 자리 | **458px** (화면의 54%가 머리말) | **266px** — 3개짜리 주가 한 화면에 (1,018 → 844px) |
| 레시피 상세의 재료 | 473px | **296px** (사진이 **없을 때만** 사진 카드를 아래로) |
| 식단 전체 길이 | 1,647px | **1,461px** |
| 메뉴 고르기 전체 길이 | 1,470px | **1,142px** |
| 정렬 | `<select>` (웹) vs 칩 (폰 앱) — **갈려 있었다** | 양쪽 다 칩 |
| 접기 | `<details>` 8곳 — 브라우저 기본 ▶ 삼각형 | `app/Fold.tsx` 한 벌 (`globals.css` 의 `.ds-fold`) |
| 하단 바 | 탭바 위에 또 한 겹, 3화면에서 | 없앴다 (가는 곳이 탭바에 이미 있었다) |
| "+ 메모" | 빈 날마다 9번 반복 | **빈 날은 줄 전체가 누르는 자리** |
| "집에 있어요" | 줄 오른쪽 끝의 파란 글씨 | 테두리를 줘서 버튼으로 |
| 카드 표지 | 사진이 없으면 제목·재료를 **또** 그림 | 사진이 없으면 표지를 안 그린다 |

**한 번 틀렸다가 되돌린 것이 둘이다.** 재료 칩을 펼쳐놨더니 도구 상자가
403 → 463px 로 늘었다. 날짜 글자만 버튼으로 만들었더니 44px 최소 높이가
빈 날 줄을 61 → 81px 로 밀어 아홉 줄에 180px 이 붙었다 —
**화면을 짧게 하려다 길게 만들었다.** 둘 다 되돌리고 다르게 풀었다.

## 4. CI — 문지기가 늘었다

| | AS-IS | TO-BE |
|---|---|---|
| 잡 | 2개 (사전·스키마 / 앱) | 3개 (+ **폰 앱** — tsc · 실제 번들 · 유출 grep) |
| UX 회귀 | 13 PASS | **16 PASS** (+ API 문지기 · 날것의 500 유출 · `recipes.cooked`) |
| 색·글자 토큰 | 없음 | **색 토큰 확인** (`verify_tokens.py`) |

`verify_tokens.py` 는 일곱 가지를 일부러 깨서 전부 빨개지는 걸 확인했다 —
토큰을 px 로 되돌리기 · 폰 앱 캡션 색만 바꾸기 · 폰 앱 액센트를 시안으로 ·
`light-dark()` 걷어내기 · `app.json` 을 `light` 로 · 화면에 색 박기 ·
`colorScheme` 을 `light` 로.

## 5. 써보고 나온 것 — 만든 메뉴는 장보기에서 빠진다

앞의 넷은 **우리가 재서** 고친 것이고, 이건 **쓰는 사람이 말한** 첫 번째다.

> 다음 주를 미리 못 정해서 그때그때 정할 때도 있고 중간에 메뉴가 바뀔 수도
> 있다. 새 메뉴를 넣으면 장보기에 추가되는 건 좋은데, 오늘 그 메뉴를
> 만들었다고 체크하면 장보기에서는 사라졌으면 좋겠다.

| | AS-IS | TO-BE |
|---|---|---|
| 만든 메뉴의 재료 | "사야 해요" 에 그대로 → **다음에 마트에서 또 산다** | 목록에서 내려간다 |
| 판정 자리 | — | `NEED_SQL` 한 군데 (`db/schema.sql` (3)번과 같은 것) |
| 여러 요리가 쓰는 재료 | — | **셋 다 만들어야** 뺀다 (`bool_and`) |
| 이미 체크(구매)한 줄 | — | **안 지운다** — 산 것이 사라지면 체크가 풀린 줄 안다 |
| 언제 만든 것으로 치나 | — | **그 주 안에.** 날짜 미정도, 하루 당겨 만든 것도 센다 |
| 되돌리기 | — | "안 먹었어요" 로 기록을 지우면 **저절로 돌아온다** (저장 안 함) |
| 다 만든 주 | "재료가 아직 안 붙어 있어요" | "담은 메뉴를 다 만들었어요. 살 것이 없어요" |
| 뺀 것을 알리는 법 | — | 합친 목록은 끝에 한 줄, 요리별은 "만들었어요" |
| 폰 앱 | — | 같이 (서버가 같은 함수를 쓴다 — API 층의 값) |

`verify_ux.ts` 에 넷을 재는 시험을 넣었다 (빠짐 · 공유 재료 남음 · 체크한 줄
남음 · 주 범위). 넷 다 일부러 깨서 각각 다른 줄에서 빨개지는 걸 확인했다.

## 안 한 것 — 그리고 왜

| 무엇 | 왜 아직인가 |
|---|---|
| **요리 중 화면** (타이머·단계 넘기기·화면 켜두기) | 만드는 법을 **단계로 쪼개는 기준**이 먼저인데, 우리 레시피의 만드는 법이 어떤 모양인지는 실제 캡처를 넣어봐야 안다. 지금 붙이면 쪼갤 단계가 없는 레시피 위에 단계 UI 를 올리게 된다 |
| **오프라인** | 지금 캐시를 켜면 장보기가 **어제 목록**을 보여줄 수 있다. 안 열리는 것보다 나쁘다. 마트에서 실제로 끊겨본 뒤에 정한다 |
| **실제 캡처 파싱 · 미분류율** | `ANTHROPIC_API_KEY` 가 있어야 한다. **나머지 판단의 근거가 여기서 나온다** — 식단·장보기는 전부 "레시피가 이미 들어와 있다" 는 전제 위에 있다 |

**정하라고 재촉하지 마라.** 지금 정하면 근거 없이 정하게 된다.

판정 기준은 그대로 하나다 — **4주 뒤 마트에서 실제로 열었는가.**
