# 이용자 흐름 · 여백 디자인 시스템 적용 검토

기준: [여백 디자인 시스템](https://github.com/data2102/design-system/tree/5e42ad5f755b9ccdb84b633d0ce283a3e1ca434d)의 foundations.md, components.md, tokens.css, components.css.
사본 두 CSS는 최신 원본과 정확히 일치한다. 새 버전 교체가 아니라 사용 방식과 앱 전용 어댑터를 개선했다.

## 문제와 반영

| 코드·화면에서 확인한 문제 | 이번 변경 |
| --- | --- |
| 긴 레시피 목록에서 담은 결과와 다음 행동이 화면 아래에 묻힘 | 담은 메뉴 수, 식단 링크, 장보기 링크를 고정 하단 바에 표시 |
| 홈 탭이 탐색 중간에 있고 검색 폼이 별도 큰 카드 | 오늘·식단을 첫 탭으로 배치, 검색은 ds-search와 한 줄 검색 버튼 |
| 두 종류의 밑줄 탭이 같은 중요도로 반복됨 | 장보기 기간은 탭, 보기 방식은 ds-chip으로 구분 |
| 장보기 수량이 재료명에서 떨어짐 | 재료명 바로 아래 원문 수량 표시 |
| 체크할 때 완료 목록이 계속 커짐 | 완료 목록을 기본 접기, 펼치면 구매 취소 가능 |
| 남은 개수만 있고 전체 준비 상태는 불명확 | ds-progress와 구매·보유 개수, 읽어주는 상태 메시지 |
| 더보기 오버레이가 Escape·포커스 제한·복귀를 구현하지 않음 | 네이티브 dialog + ds-modal로 변경 |
| 보조 글자 대비와 포커스 표시가 화면마다 다름 | 핵심 화면 보조 글자에 secondary 토큰, 공통 focus-visible 표시 |

## 유지한 조건

냉장고 재료 입력은 강제하지 않는다. 상시 재고 관리나 추가 입력을 요구하지 않는다.
원문 재료·수량을 보존하고 단위 환산을 추정하지 않는다. DB 스키마·구매 판정 로직은 변경하지 않는다.
공통 CSS는 수정하지 않고 앱 전용 배치·접근성 어댑터만 사용한다.

## 검증 범위와 한계

빌드·린트 및 테스트 DB를 이용한 Chromium 화면·동작 검증을 수행한다.
실제 사용자 관찰이나 사용 시간 측정 결과는 아니다. 편의성 향상은 설계 의도이며,
실사용에서 메뉴 선택과 마트 체크가 더 쉬워졌는지는 후속 피드백으로 확인해야 한다.
